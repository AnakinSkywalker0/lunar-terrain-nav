## State in one paragraph
A literature-verification PDF showed several LANTERN headline results came from experiment design. I audited them, re-scored old runs,
built a headless Unity pipeline, and ran 21,888 new descents on 12 Site01 areas. Outcomes: the "shifted map unsolved" claim was a scoring
artifact; small realistic tie errors are harmless in this sim; speed violations come from wrong fixes under unmodelled relief; the
pre-registered authority-aware gate (G2) failed; a classical Kalman + chi-square gate clearly beat both plain matching and the learned
policy and survived accelerometer bias. The project is a solid engineering and evaluation effort, not yet a paper (see Explainer section 4).

## Known issues and caveats
- Simulator limits: 3-DOF, ideal attitude, instantaneous scans, Gaussian-bump relief (four shapes shared by every area), three fixed start
  errors, one DEM tile (Site01) for the new runs. All results are simulation-only.
- Map-shift failures (29%) sit in one start error (u2). Search-window explanation is an inference; widening the window was not tested.
- Per-scan "wrong / harmful / useful" labels depend on each arm's own trajectory; map-shift rows are not interpretable.
- The 0.3-0.5 m DEM error figure is now verified (see PGDA note below). NASA 50/100 m requirements and the novelty claims come from the 29 Oct note and are not re-verified. Verified 9 Nov 2026 on NASA's PGDA product 78 page: 0.30-0.50 m median height RMS, 10-20 cm track geolocation, about 90% of 5 m pixels interpolated, 100 Monte Carlo clones listed per site (clone file availability and size not checked).
  My own literature check was about 10 web searches (snippets only, two failed fetches); it is not exhaustive.
- The learned policy may look weak because it is small and trained on Site04; it was not retrained.
- The old docs (`README.md` body, `docs/PROJECT_EXPLAINED_AND_REFOCUSED.md`, 5 deliverable PDFs) still contain claims the audit contradicts
  (shifted map "unsolved", IM-1/IM-2 accounts, "90 m field test", Choe 2022 citation). Only the README got a notice.
- `tools/rescore_thresholds.py` still prints per-run Wilson intervals in `rescored_by_condition.csv`; they treat runs as independent and
  should be ignored (the newer scripts use areas as the unit).
